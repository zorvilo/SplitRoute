# 架构与边界

## 依赖方向

```text
frontend/components → composables/useRouting → api.ts
                                              ↓ Tauri IPC
src-tauri/commands → application → domain
                         ↑
              infrastructure/network、storage
```

Vue 组件负责布局、输入和无障碍语义；composable 管理操作状态、错误与刷新。`api.ts` 是唯一 IPC 调用入口，类型中网卡 LUID 用字符串传输，避免 JavaScript 64 位整数精度丢失。

Tauri 命令处理互斥、权限检查和 DTO 边界；应用层依赖 Network、Journal 两个 trait，编排校验、持久化、变更、验证与补偿。领域层只包含数据模型和纯规则，不依赖 Tauri 或 Windows。基础设施层集中处理 Windows unsafe API 和持久化。

保持一个 Rust crate。模块边界已经足够隔离当前规模的功能，不增加多 crate、服务容器、通用仓储或后台服务。

## 路由操作

1. 重新枚举在线网卡，校验两个接口、CIDR、单播网关及直连网段。
2. 有本次开机的撤销记录时拒绝再次启用；第三张网卡存在默认路由时拒绝修改。
3. 保留匹配的外网默认路由，记录其他待移除的默认路由和待新增路由。
4. 在第一次系统修改前，把完整操作意图同步到磁盘并替换正式记录。
5. 先新增目标路由，再移除竞争默认路由；读取实际路由表验证，失败时自动回滚。
6. 撤销前检查开机标识、两张网卡的地址/网关与相关路由，再反序撤销并逐项验证、更新记录。相关状态变化时停止，不强行恢复。

恢复比较接口、网段、网关、metric 和 protocol；发现外部冲突时保留记录并停止，避免覆盖已变化的路由。网络状态在检查与写入之间仍可能变化，系统 API 错误会进入补偿流程。

这不是操作系统级事务，不保证其他路由管理软件并发改动时的原子性。DHCP 续租、重启和换网也可能使旧路由不再适用。

## 存储

`%LOCALAPPDATA%/SplitRoute/config.json` 保存最后一次有效配置；`recovery.json` 保存版本 3 撤销记录，包含开机标识、有效配置、两张网卡和操作清单；`preferences.json` 保存设置。临时文件写入并 flush 后使用 Windows 替换操作提交。

仅处理当前 JSON 格式，不导入或转换其他格式。不同开机标识的记录只保留、不执行，不计入待撤销状态；再次启用时以当前记录替换。Windows 10/11 通过 SystemBootEnvironmentInformation 的 BootIdentifier 识别本次开机；读取失败时停止路由操作。

## 权限与安全

- Release EXE 通过 manifest 请求管理员权限；Debug 普通启动，修改命令再次验证 token 权限。
- 单实例插件避免两个新版进程同时写恢复记录；命令互斥防止一个进程内并发操作。
- 路由命令只有 snapshot、enable、restore。设置命令使用固定的当前用户任务脚本、固定 GitHub API 和项目链接，不开放任意 shell、任意 URL 或文件接口。
- 页面资源随应用本地打包，CSP 限制脚本与连接来源。
- 当前仅 IPv4 路由分流；不修改 DNS，不阻止 IPv6，也不保证绕过更具体的现有路由。

## 视觉规范

遵循用户提供的 CC Switch 参考：白底 #FFFFFF、强调蓝 #2085FF、正文 #202632、辅助文字 #7B8190、边框 #E4E5EC。系统 UI 字体，无外部字体下载。卡片承载出口配置，按钮层次区分启用、恢复、检查；下拉框使用 Reka UI 的键盘与焦点语义，统一样式在 styles.css。

## 验证

Rust 内存替身测试覆盖应用流程和补偿；存储测试在临时目录写入，网络读取测试仅枚举本机网络，不修改路由。前端测试覆盖明确选择不同网卡、错误后恢复状态刷新、断开网卡后清空选择。

真实双网卡路由变更需要在可恢复网络环境验收，不能由上述单元测试代替。

## 设置与桌面行为

`settings.rs` 负责偏好类型与命令；登录任务系统调用集中于 `infrastructure/startup.rs`，GitHub 请求集中于 `infrastructure/releases.rs`，托盘与窗口生命周期集中于 `desktop.rs`。登录任务默认不注册，不自动启用路由。关闭到托盘默认关闭。

偏好在 Rust JSON 中持久化，前端仅缓存语言和主题以避免启动闪烁。前端用统一字典即时切换四种语言；系统返回的详细错误保留原文。跟随系统使用 prefers-color-scheme，同时同步原生标题栏主题。

## 状态判断

已生效：配置的内网路由存在，外网默认路由存在，没有其他默认出口，且本次记录的网卡环境仍匹配。未启用：无本次操作且未匹配目标路由。配置已变化：有本次撤销记录但实际状态不匹配。读取失败显示无法判断。记录存在只控制撤销入口，不等同于分流生效。

主动移除内网默认路由可能使 Windows 网卡枚举不再返回该网关；只对本次操作清单中明确移除的同一网关允许此差异，其他网关变化仍停止撤销。

## 侧栏连通性

`AppSidebar.vue` 组装三个导航入口与底部 `ConnectivityPanel.vue`。`useConnectivity.ts` 管理采样、最近 30 点历史、无重叠请求、参数变化后丢弃旧结果、隐藏暂停与卸载清理。`connectivity.ts` 生成连续有效采样的 SVG 路径，超时使用 null 留空，不伪造流量或延迟。

`probe_connectivity` 是独立异步只读命令，不持有路由服务锁。`infrastructure/connectivity.rs` 刷新在线网卡，检查目标与源地址，通过 GetBestRoute2 核对当前出口，再使用 IcmpSendEcho2Ex 指定源地址。内外网并行探测、每次超时 800 ms，不改路由。固定公网目标是 223.5.5.5；图表只是 ICMP 指标，不保证 DNS、互联网应用或公司业务可用。

连通检测每秒采样一次，重叠请求跳过。图表两条路径保持固定 DOM 节点，延迟轴按 100 ms 起的分档范围缩放；每个真实新样本到达时只平移图组，动画不生成额外探测或虚构数据。尊重减少动态效果偏好，卸载时取消动画。
